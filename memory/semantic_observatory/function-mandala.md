## Circular Function Projection

---

# Purpose

The Function Mandala is the primary semantic projection model for visualizing functions inside the Semantic Observatory.

Rather than representing a function as a linear list of statements, the Function Mandala treats a function as a **constructive circular field**.

Its geometry reflects semantic organization rather than source-code formatting.

The objective is not artistic decoration, but semantic readability through deterministic geometric construction.

The Function Mandala is the first projection grammar built upon the Geometric Field Engine.

# Core Principle

A function should not appear as a vertical sequence of statements.

Instead, it should emerge as a circular semantic construction whose geometry expresses:

* intention
* transformation
* control flow
* data flow
* semantic phases
* interaction with other functions

Geometry therefore becomes a semantic language rather than a decorative language.

---

# Function Core

Every Function Mandala possesses a single semantic center.

The center represents the identity of the function.

It contains:

* function name
* semantic purpose
* optional documentation summary

The center is considered the origin of the entire construction.

Every visible component must possess a constructive lineage back to this center.

---

# Central Generation Principle

Nothing inside the Function Mandala should appear disconnected.

Every visible element must originate directly or indirectly from the function center.

Construction therefore follows the same philosophical principle established by the Geometric Field Engine.

---

# Input Boundary

Function parameters occupy the outer input boundary.

Inputs are projected onto radial directions surrounding the function.

Each parameter possesses:

* radial direction
* semantic role
* optional type
* optional default value

Inputs flow toward the function center.

---

# Output Boundary

Function outputs occupy the outer output boundary.

Outputs represent the completion of semantic transformation.

Return values should emerge from the outer construction rather than appearing inside the computational core.

---

# Concentric Semantic Rings

The Function Mandala is composed of semantic rings.

Each ring represents a different level of semantic organization.

Suggested layers:

Ring 1

Input context

Ring 2

Transformations

Ring 3

Temporary semantic state

Ring 4

Output preparation

Ring 5

External communication

The exact interpretation of each ring remains configurable.

---

# Structural Projection

The structural layer displays:

* parameters
* local variables
* constants
* return values
* nested scopes

No execution information is displayed in this layer.

---

# Control-Flow Projection

Control flow is projected as directed circular paths.

Execution progresses around the mandala instead of down a source-code listing.

Branches become geometric splits.

Merge points become geometric convergence.

---

# Data-Flow Projection

Data dependencies form an independent overlay.

Variables become semantic carriers rather than simple textual identifiers.

The Data-Flow layer may be enabled or hidden independently from the structural layer.

---

# Loop Sub-Rings

Loops create secondary circular constructions.

A loop is not represented merely as an arrow.

Instead, it becomes a nested circular field inside the parent Function Mandala.

Each loop possesses:

* entry point
* iteration path
* exit point

Nested loops generate nested circular constructions.

---

# Conditional Branches

Conditional statements generate branching arcs.

Each branch possesses:

* decision point
* branch path
* merge point

Multiple branches remain visually attached to the parent construction.

---

# Function Calls

Invoked functions become satellite centers surrounding the current Function Mandala.

Satellite centers remain collapsed by default.

Selecting a satellite recenters the entire Semantic Geometric Field around the selected function.

The transition should preserve geometric continuity.

---

# Projection Layers

Every Function Mandala supports multiple independent projection layers.

Possible layers include:

* Structural Layer
* Control-Flow Layer
* Data-Flow Layer
* Phase Layer
* Call Layer
* Documentation Layer
* Complexity Layer
* Type Layer

Each layer may be enabled independently.

The underlying geometry remains unchanged.

---

# Interaction Model

Selecting any semantic object should preserve spatial continuity.

Possible interactions include:

* recenter function
* replay construction
* isolate semantic layer
* expand nested loop
* expand satellite function
* compare two functions
* follow data flow
* follow control flow

Transitions should interpolate between geometric states rather than replace layouts.

# Long-Term Vision

The Function Mandala represents only the first semantic projection grammar.

Future projection grammars may include:

* Module Mandala
* Class Mandala
* Package Mandala
* Workspace Mandala
* Program Mandala

Each projection grammar should reuse the same Geometric Field Engine while expressing different semantic scales.

---

# Design Philosophy

The Function Mandala is not intended to imitate mystical diagrams.

Its purpose is to reveal semantic organization through constructive geometry.

Any sense of beauty should arise from coherent geometric construction rather than ornamental complexity.

The visualization should therefore feel inevitable rather than decorative.

---

# Core Principle

> A function shall not be represented as lines of code.

> It shall emerge as a circular semantic construction whose geometry expresses intention, transformation, flow, and completion.

The Function Mandala is therefore both a visualization model and a semantic language built upon geometry.
