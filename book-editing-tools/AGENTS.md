# AGENTS.md — book-editing-tools

For ordinary use, read only the selected sub-tool's `SKILL.yaml` and example; use `README.md` when selecting among book tools or navigating code. The audits and `chapter_plan` are read-only; `docx_assemble` may create a new DOCX only after a matching dry-run preview. Run `manuscript_inventory` first when the input structure is unfamiliar. Keep uncertain matches visible in the result; never silently edit manuscripts or interpret thematic relationships as facts. User-authored spellings, order, and editorial decisions remain authoritative. Use a document renderer for any claim about page layout or final EPUB appearance.

When extending a sub-tool, keep its stdin JSON and Python API aligned, update its metadata and registry entry, and test normal, invalid, and boundary inputs. Put source parsing in `manuscript_sources.py`, inventory construction in `inventory_core.py`, audits in `audit_core.py`, and plan types in `book_model.py`. Keep `common.py` as the stable compatibility/JSON entrypoint; do not add new business logic there. Keep DOCX assembly's preflight, mutation, and verification stages separate in `docx_assemble_core.py`. Avoid one-off scripts in a chat.
